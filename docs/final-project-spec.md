успешный путь: команда add → проверка title и priority → создание Task → добавление через PlannerService → сохранение через JsonStorage → подтверждение пользователю

путь чтения: запуск программы → JsonStorage.load → список Task → форматирование → вывод

три ошибочных сценария: пустой title, priority вне 1-5, повреждённый JSON

### работает сейчас:

## add_task: 

1) запуск программы командой python -m app.main
2) создание переменной хранящей путь к файлу tasks.json
3) вызов функции run(), в случае если запущенный файл имеет название __main__
4) создание переменной storage, отвечающей за хранение данных (Json/В памяти программы)
5) создание перемеенной services, отвечающей за вызов функций для работы с задачами
6) вызов команды show_menu() из cli.py
7) отображение пользователю меню

6. Показать статистику

8. Выйти

вывод пользователю:

12) если приоритет не введен, задаем приоритету значение 3

13) запрос тегов задачи и получение тегов от пользователя
вывод пользователю:

14) разбиваем введеные пользователем через пробел строки (тэги) методом split()

15) через переменную service (э.к. PlannerService) вызываем метод add_task и передаем в него аргументы title, priority и tags
16) отлавливаем ошибки связанные с некорректностью введенных данных (пустое название, 1 <= приотрет <= 5)

вывод пользователю:

Название не может быть пустым
Приоритет должен быть от 1 до 5

17) в services, переменной tasks присвавивает результат выполнения метода load, вызванного через переменную storage, переданную при создании переменной services в main (э.к. JsonStorage/MemoryStorage)
18) проверяем не пустой ли список, если список пуст создаем переменную next_id со значением 1
19) иначе если длинна tasks равна еденице, создаем переменную next_id со значением 2
20) иначе, создаем переменную next_id со значением равным айди первой задачи из tasks
21) ищем максимальный id среди текущих задач и присваиваем переменной next_id значение на 1 больше максимального id в tasks
22) создаем переменную task, которая создает э.к. Task с переданными аргументами  (title, priority, tags)
23) добавляем в tasks переменную task
24) у переменной storage вызываем метод save и передаем в него tasks
25) возвращаем task
26) выводим пользователю информацию об успешном добавлении задачи:

вывод пользователю:

Задача добавлена в tasks

## Команда find

Вход: id задачи
Успех: функция возвращает значение по заданному id, список не изменяется
Ошибка: неизвестный id даёт TaskNotFoundError
Состояние: состояние tasks не изменяется

## Команда mark_done

Вход: id задачи
Успех: задача с заданным id поулчает значение is_done = True, обновленный список сохраняется
Ошибка: неизвестный id даёт TaskNotFoundError
Состояние: состояние tasks изменяется

## Команда get_stats

Вход: 
Успех: функция возвращает строку с количеством выполненных и не выполненных задач
Ошибка: 
Состояние: состояние tasks не изменяется

## Команда get_tasks

Вход: 
Успех: функция возвращает список э.к. Task
Ошибка: 
Состояние: состояние tasks не изменяется

## Команда remove_task

Вход: id задачи
Успех: задача с заданным id удаляется из tasks, обновленный список сохраняется
Ошибка: неизвестный id даёт TaskNotFoundError
Состояние: состояние tasks изменяется

## Команда add_tags

Вход: id задачи, список тегов
Успех: задаче с заданным id добавляются теги, которых ранее у неё не было, обновленный список сохраняется
Ошибка: неизвестный id даёт TaskNotFoundError
Состояние: состояние tasks изменяется

При первом запуске, в main будет создан файл, в который будут записываться задачи
нет файла → []

Если json-файл поврежден при вызове функции load, будет сгенерировано искл.чение StorageError, которое покажет где именно поврежден json-файл

Формат сохраняемой записи:

  {
    "id": 1,
    "title": "qwe",
    "priority": 3,
    "is_done": true,
    "tags": [
      "fdsg",
      "sgdfh"
    ]
  }

FastAPI, база данных, ORM, авторизация и Docker не входят в этот проектный этап
